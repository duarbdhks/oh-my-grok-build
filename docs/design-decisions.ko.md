# 설계 결정

[English](design-decisions.md)

제품 경계에 대한 짧은 결정 로그입니다. 전체 upstream 포크 대비 재설계 근거: [업스트림 평가](upstream-evaluation.ko.md).

## DD-001 — 콘텐츠 전용 플러그인

**결정:** 스킬·에이전트를 마크다운으로만 제공한다. 훅, MCP, LSP, 바이너리, npm 런타임 의존성 없음.

**이유:** Grok Build 신뢰·권한 모델 안에 남긴다. 설치 면과 보안 검토 비용을 줄인다.

## DD-002 — 네이티브 우선 오케스트레이션

**결정:** 세션 저장, goal 상태머신, 워크트리 관리자, 워크플로 엔진을 재구현하지 않는다.

**이유:** 이미 Grok Build가 소유한다. 중복은 드리프트와 가짜 연속성 주장을 만든다.

## DD-003 — 계획과 실행 분리

**결정:** `/ogb-plan`은 구현하지 않는다. 실행은 이후 명시적 `/ogb-start`, `/ogb-ultrawork`, 또는 네이티브 `/goal`이 필요하다.

**이유:** 모호한 채팅이 미검토 소스 수정으로 바로 가는 것을 막는다.

## DD-004 — 독립 검증

**결정:** 최종 게이트는 구현자 자기 보고가 아니라 `oh-my-grok-build:verifier`(및 가능하면 `check-work`)를 쓴다.

**이유:** 자신감은 증거가 아니다. 자기 승인은 멀티 에이전트 실패 모드다.

## DD-005 — 제한된 병렬

**결정:** 소유권 금지, 격리 상한, 잔여 child 예산, 워크플로 예산이 있는 max-safe 동시성.

**이유:** 무제한 팬아웃은 빨라 보이지만 공유 파일·포트·락에서 실패한다.

## DD-006 — 한정 에이전트 이름

**결정:** 파일명은 짧은 이름(`executor.md`)이지만 spawn은 `oh-my-grok-build:executor`.

**이유:** Grok이 플러그인 에이전트를 네임스페이스한다. bare 이름은 같은 짧은 이름의 사용자 에이전트로 갈 수 있다.

## DD-007 — 명시적 비용, 조용한 폴백 금지

**결정:** 스킬 계약에서 모델/도구/MCP 조용한 폴백 경로를 두지 않는다. 실패를 드러낸다.

**이유:** 조용한 저하가 가짜 PASS 서사를 만든다.

## DD-008 — 지시로 Git 보호

**결정:** 사용자 명시 요청 없이는 commit/push/PR/force-reset을 금지한다.

**이유:** 진행 중 사용자 작업을 보호한다. 권한은 여전히 Grok Build에 있다.

## DD-009 — heavy 스킬에 disable-model-invocation

**결정:** 스킬 7개 모두 `disable-model-invocation: true`.

**이유:** 일반 생성이나 `/goal` 안에서 사용자 의도 없이 오케스트레이션이 돌지 않게 한다.
