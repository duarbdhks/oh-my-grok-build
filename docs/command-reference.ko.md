# 명령 참고

[English](command-reference.md)

제공되는 스킬 7개는 모두 `disable-model-invocation: true`입니다. 사용자가 호출하지 않는 한 일반 채팅이나 `/goal`에서 조용히 자동 실행되지 않습니다.

에이전트는 반드시 `oh-my-grok-build:<name>`으로 spawn 합니다.

---

## `/ogb-interview`

| 항목 | 내용 |
|---|---|
| 목적 | 모호한 아이디어를 의사결정 가능한 방향 브리프로 |
| 입력 | 거친 아이디어, 검증할 설계, 불완전한 요구사항 |
| 소스 수정 | 없음 |
| 병렬 | 저장소 사실 확인용 읽기 전용 explorer 가능, 구현자 없음 |
| 에이전트 | 조사가 필요하면 `oh-my-grok-build:explorer` |
| 산출물 | 승인 대기 방향 브리프 |
| 실패 시 | 강한 모호성에서 중단, 계획·코드 창작 금지 |
| 안전장치 | 턴당 질문 1개, 저장소가 답할 수 있는 질문은 금지, commit/push 없음 |

**네이티브 경계:** 구현 계획을 저장하지 않습니다. `/ogb-plan`으로 넘깁니다.

---

## `/ogb-plan`

| 항목 | 내용 |
|---|---|
| 목적 | 코드 변경 없이 합의 구현 계획 |
| 입력 | 구체적 결과, 또는 `/ogb-interview` 브리프 |
| 단계 | 근거 수집 → 탐색 → planner 초안 → architect → critic (최대 3루프) |
| 소스 수정 | 없음 |
| 에이전트 | `explorer`, `planner`, `architect`, `critic` (한정 이름) |
| 산출물 | 네이티브 저장 계획, `pending approval` |
| 실패 시 | 너무 모호하면 interview로, 미완성 계획은 critic 거부 |
| 안전장치 | Plan mode 선행, 실행 스킬 호출 금지 |

**네이티브 경계:** `/view-plan` 등으로 저장·검토. 구현하지 않음.

---

## `/ogb-start`

| 항목 | 내용 |
|---|---|
| 목적 | 승인된 계획을 소유권 기반으로 실행 |
| 입력 | `current-saved-plan`, `explicit-plan-path`, 또는 좁은 `concrete-task` |
| 소스 수정 | 작업 소유 범위 안에서 있음 |
| 병렬 | 기본은 의존 웨이브, 독립 작업은 워크트리 격리 executor 가능 |
| 에이전트 | `explorer`, `executor`, 이후 `verifier` 경로 |
| 산출물 | 구현 + 실행 보고 증거 |
| 실패 시 | 제한된 수리 후 중단, 무관한 사용자 변경 보존 |
| 안전장치 | 명시 요청 없이 commit/push/PR/deploy 금지 |

**네이티브 경계:** 워크트리·세션 재개는 Grok Build 소유. OGB는 수명주기만 보고.

---

## `/ogb-ultrawork`

| 항목 | 내용 |
|---|---|
| 목적 | 독립 작업의 elapsed time을 제한된 네이티브 병렬로 단축 |
| 입력 | 소유권이 겹치지 않는 작업 2개 이상과 명확한 수용 기준 |
| 소스 수정 | 소유권 규칙 하에서 있음 |
| 병렬 | max-safe `C*` (기본 iso 4, 증명 시 8, 공유 자원 시 2); 워크플로 예산 기본 8 |
| 에이전트 | 기본 `executor`/`explorer`만, 각 child에 닫힌 `ROLE_LENS` |
| 산출물 | 병렬 리포트 (동시성, 에이전트, 검증, 위험) |
| 실패 시 | 조용한 메커니즘 교체 없음, 같은 파일 동시 소유 금지 |
| 안전장치 | 대규모 스키마형 팬아웃은 네이티브 워크플로 선호, 외부 오케스트레이터 없음 |

---

## `/ogb-verify`

| 항목 | 내용 |
|---|---|
| 목적 | 주장·수용 기준의 독립 재검증 |
| 입력 | diff 범위, 계획 기준, 또는 “현재 변경” |
| 소스 수정 | 없음 |
| 병렬 | 읽기 전용 점검 배치 가능, 별도 요청 없이 수정하지 않음 |
| 에이전트 | `oh-my-grok-build:verifier` (+ 가능하면 `check-work`) |
| 산출물 | `PASS` / `FAIL` / `INCONCLUSIVE` 검증 리포트 |
| 실패 시 | 재현 가능한 증거 반환, 조용한 성공 표시 금지 |
| 안전장치 | 최신 명령 선호, 구현자 요약만으로 승인 금지 |

---

## `/ogb-workflow`

| 항목 | 내용 |
|---|---|
| 목적 | OGB 안전 가드와 함께 재사용 워크플로 작성 |
| 입력 | 반복 다단계 프로세스를 워크플로로 만들 요청 |
| 소스 수정 | 작성 시 워크플로 정의 파일 가능, 기본 앱 기능 범위 아님 |
| 병렬 | 워크플로 내부 정의, 기본 `agent_budget` 8 |
| 에이전트 | 네이티브 `create-workflow` 경로 |
| 산출물 | 검증된 워크플로 스크립트/저장 정의 |
| 실패 시 | 라이브 실행 제안 전 `validate_only` 스모크 필수 |
| 안전장치 | 유한 입력, 중첩 워크플로 금지, 외부 부수효과는 승인 필요 |

**네이티브 경계:** 실행·일시정지·재개·저널은 Grok이 소유. 별도 런타임을 만들지 않음.

---

## `/ogb-doctor`

| 항목 | 내용 |
|---|---|
| 목적 | 플러그인 설치·컴포넌트 발견·네이티브 전제 진단 |
| 입력 | 선택적 `--fix-plan` |
| 소스 수정 | 기본 읽기 전용 |
| 산출물 | PASS/WARN/FAIL 리포트 |
| 안전장치 | 네이티브 `/doctor`, `grok inspect`를 보완 |

---

## 선택 매트릭스

| 상황 | 명령 |
|---|---|
| 모호한 아이디어 | `/ogb-interview` |
| 안전한 계획 필요 | `/ogb-plan` |
| 승인된 계획, 순차 실행 | `/ogb-start` |
| 독립 병렬 작업 | `/ogb-ultrawork` |
| 증거 재확인 | `/ogb-verify` |
| 재사용 멀티 에이전트 프로세스 | `/ogb-workflow` |
| 설치 이상 | `/ogb-doctor` |
